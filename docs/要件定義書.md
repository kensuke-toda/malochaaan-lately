## 1. プロダクト概要

**Lately** は、Ken とパートナーの2人で運用する近況報告サイト。買ってよかったモノ（Things）と日々の出来事（Diary）を、なるべく手間なく記録・公開することを目的とする。

- **主用途**: 2人の記録＋知人に「最近何してるか」を見せる公開ページ
- **ユーザーモデル（🚧 方針変更）**: Ken・パートナーの2アカウント。**1つの公開ページを2人で共有**し、それぞれが自分のアカウントでログインして投稿する（`my-app`のhousehold型に近い、専用の家庭グループ概念は持たない固定2アカウント運用）。投稿には誰が書いたかが分かるよう投稿者名を表示する
- **公開範囲**: トップページ・詳細ページ（Things・Diary・Places共に）は誰でも閲覧可能（読み取り全公開）。投稿・編集は各自のログイン後のみ可能
- **🆕 投稿の起点**: `/admin`という別画面には依存しない。**ログイン中はTOPページ上に各セクションの「＋追加」ボタンが現れ、モーダルでその場から投稿できる**（Things／Diary／Places共通のパターン）
- **🆕 カレンダー**: TOPページにカレンダー（月表示）を置き、日付ごとに「その日に追加されたThings／Diary／Places」を色分けドットで示す。日付をクリックするとその日の投稿一覧を表示する
- **🆕 デザイントーン**: スタイリッシュ・ミニマルではなく、**温かみのあるミッドセンチュリー・モダン**（マスタード・テラコッタ・カーキ系の色、クリーム背景、丸みのある形、セリフ寄りの見出しフォント）

### やらないこと（明確な非スコープ）

- 3人以上のユーザー対応、オープンなサインアップ（アカウントは2人分のみ、Ken自身がSupabaseダッシュボードで手動発行）
- コメント機能・いいね機能などのソーシャル要素
- Places（お店）の**3Dジオラマ演出**（写真をそのまま使うシンプル版のみPhase 1に含む。ジオラマ生成は引き続き見送り）
- Books/Sounds/Posts/Worksセクション（将来検討、Phase 3以降）
- Things一覧の並び替えUI・モノ日記の編集機能（Phase 1では対象外。削除して追加し直す運用でカバー）
- 独自ドメイン（Phase 1は `*.vercel.app` のまま運用）

## 4. 機能仕様

### 4.1 認証（管理画面）※方針変更中

**現行実装（変更前）**: Supabase Authは使わず、環境変数 `ADMIN_PASSWORD` と一致するパスワードでログイン。`lately_admin_session` Cookie（パスワードのSHA-256ハッシュ）で認証状態を管理。

**新方針（実装予定）**:

- Supabase Authのメール＋パスワード認証を使用。アカウントは2つのみ（Ken・パートナー）で、**サインアップ画面は作らない**。Ken自身がSupabaseダッシュボードで2アカウントを手動作成する運用（決定済み）
- `profiles` テーブル（`id` は `auth.users.id` と1:1、`display_name` を持つ）を新設し、投稿者の表示名を解決する
- `things` / `diary_entries` に `created_by`（`auth.users.id`）カラムを追加し、誰の投稿か記録する
- ログイン後の `/admin` はどちらのアカウントでもモノ・日記の追加ができる。**編集・削除は自分の投稿のみ**（決定済み。パートナーの投稿は編集・削除不可）
- RLS: `select` は引き続き全公開。`insert` は認証済みユーザーのみ（`created_by = auth.uid()` を強制）。`update`/`delete` も `created_by = auth.uid()` の行のみ許可
- 公開ページ（トップ・詳細）で投稿者の表示名を表示する

この変更に伴い、既存の `ADMIN_PASSWORD` ベースの実装（`src/lib/admin-auth.ts`）は撤去し、Supabase Authのセッション管理に置き換える。

### 4.2 Things（モノ図鑑）

**データ項目**

| 項目 | 必須 | 内容 |
|------|------|------|
| 商品名 (`name`) | ○ | |
| ブランド名 (`brand`) | × | |
| 商品ページURL (`product_url`) | × | クリックで外部遷移 |
| 元画像 (`original_image_url`) | × | 管理画面からアップロード、`things-images` バケットに保存 |
| 透過済み画像 (`processed_image_url`) | × | **Phase 1では自動生成しない**。用意できる場合は事前に加工した画像をアップロードする運用でカバー |
| メモ (`memo`) | × | |
| 並び順 (`sort_order`) | × | デフォルト0（将来の手動並び替え用。Phase 1のUIからは変更不可） |

**表示ロジック**: `processed_image_url` があればそれを、無ければ `original_image_url` を表示する。

**操作**: TOPページの「＋追加」ボタン→モーダルでフォーム一括追加。削除（一覧から即削除、確認ダイアログなし）は`/admin`から。編集機能はPhase 1では未実装（削除して追加し直す運用）。

### 4.3 Diary（日記）

**データ項目**

| 項目 | 必須 | 内容 |
|------|------|------|
| タイトル (`title`) | ○ | |
| 本文 (`body`) | × | 複数行テキスト |
| 日付 (`entry_date`) | × | 未指定時は今日の日付 |
| 写真 (複数、`diary_photos`) | × | 複数ファイル選択でまとめてアップロード、`diary-images` バケットに保存。`sort_order`はアップロード順 |

**操作**: TOPページの「＋追加」ボタン→モーダルでタイトル・本文・日付・複数写真を1フォームで追加。削除（紐づく `diary_photos` もCASCADE削除）は`/admin`から。編集機能はPhase 1では未実装。

### 🆕 4.4 Places（お店）

参考記事の「Places」に相当。**3Dジオラマ演出は行わず**、写真＋メモのシンプル版。

**データ項目**

| 項目 | 必須 | 内容 |
|------|------|------|
| 店名 (`name`) | ○ | |
| 訪問日 (`visited_date`) | × | 未指定時は今日の日付。カレンダー表示のキーになる |
| 写真 (`image_url`) | × | 店の外観・内観など。TOPページのモーダルからアップロード、`places-images` バケットに保存 |
| メモ (`memo`) | × | 「誰と行ったか」「何が良かったか」等 |

**操作**: TOPページの「＋追加」ボタン→モーダルで店名・訪問日・写真・メモを1フォームで追加。削除は`/admin`から。編集機能はPhase 1では未実装。

### 4.5 公開ページの表示ロジック

- トップページ: `things` を `sort_order`昇順→`created_at`降順で最大24件、`diary_entries` を `entry_date`降順で最大10件（写真同時取得）、🆕 `places` を `visited_date`降順で最大24件
- 詳細ページ: `id` 指定で1件取得、存在しなければ404 (`notFound()`)
- Supabase未設定（環境変数がプレースホルダーのまま）の場合、公開ページはエラーにせず「Supabaseが未設定です」という案内を表示し、詳細ページは404を返す

### 🆕 4.6 カレンダー

- TOPページに月表示のカレンダーを設置
- 各日付セルに、その日の投稿種別を色分けドットで表示：Things=マスタード、Diary=ティール、Places=テラコッタ（複数種別があれば複数ドット）
- 日付をクリックすると、その日の投稿一覧（Things／Diary／Places横断）をカレンダー下に表示する
- 対象日の判定キー：Things=`created_at`の日付部分、Diary=`entry_date`、Places=`visited_date`
- 月送り（前月／今月／次月）は最低限対応

## 5. 技術アーキテクチャ

```
[ブラウザ（公開ページ / 管理画面）]
        │
        ▼
[Next.js (App Router) + TypeScript]  ── Vercel にデプロイ予定
   │
   ├── Server Components: 公開ページの読み取り（anonキー、RLSに従う）
   ├── Server Actions (/admin/actions.ts): 書き込み（Service Roleキー、RLSを迂回）
   │
   ▼
[Supabase]
   Database（things / diary_entries / diary_photos）+ RLS
   Storage（things-images / diary-images、公開読み取りバケット）
```

| 層 | 技術 |
|----|------|
| フロントエンド | Next.js (App Router), React, TypeScript, Tailwind CSS |
| バックエンド/DB | Supabase（Database, Storage）※Authは不使用 |
| ホスティング | Vercel（Hobbyプラン、無料枠） |
| 画像表示 | `next/image` は使わず素の `<img>` タグ（remotePatterns設定を省略するため） |

### 主要ソースマップ

## 6. データモデル

現行スキーマ（実装済、`supabase/schema.sql`）:

```
things
  id (uuid, PK)
  name (text, not null)
  brand (text, null可)
  product_url (text, null可)
  original_image_url (text, null可)
  processed_image_url (text, null可)
  memo (text, null可)
  sort_order (integer, default 0)
  created_at (timestamptz, default now())

diary_entries
  id (uuid, PK)
  title (text, not null)
  body (text, null可)
  entry_date (date, default current_date)
  created_at (timestamptz, default now())

diary_photos
  id (uuid, PK)
  diary_entry_id (uuid, FK -> diary_entries.id, on delete cascade)
  image_url (text, not null)
  sort_order (integer, default 0)
```

**🚧 方針変更後に追加予定**:

```
profiles
  id (uuid, PK, FK -> auth.users.id)
  display_name (text, not null)

things.created_by      (uuid, FK -> auth.users.id, not null)
diary_entries.created_by (uuid, FK -> auth.users.id, not null)

-- 🆕 Phase 1に前倒し
places
  id (uuid, PK)
  name (text, not null)
  visited_date (date, default current_date)
  image_url (text, null可)
  memo (text, null可)
  created_by (uuid, FK -> auth.users.id, not null)
  created_at (timestamptz, default now())
```

**RLS方針（変更前）**: 3テーブルとも `select` は全公開（`using (true)`）。`insert`/`update`/`delete` のポリシーは意図的に作成せず、Service Roleクライアント（RLSを迂回）のみが書き込み可能。

**RLS方針（変更後・予定）**: `select` は引き続き全公開。`insert` は認証済みユーザーが `created_by = auth.uid()` で自分の投稿として作成。`update`/`delete` は **`created_by = auth.uid()` の行のみ**許可（自分の投稿のみ編集・削除可、決定済み）。

**Storage**: `things-images` / `diary-images` / 🆕 `places-images` の3バケット、どちらも `public: true`（読み取り公開）。書き込みは変更前はService Role経由のみ、変更後は認証済みユーザーからの直接アップロードに変える想定（Storageポリシーの追加が必要）。

## 7. 受け入れ条件（Phase 1）

1. `supabase/schema.sql` を実行したSupabaseプロジェクトに接続すると、トップページでThings/Diaryが表示される
2. `/admin` に正しいパスワードでログインできる。誤ったパスワードではログインできない
3. 管理画面から画像付きでモノを追加すると、`things-images` バケットにアップロードされ、トップページに反映される
4. 管理画面から複数写真付きで日記を追加すると、`diary-images` バケットにアップロードされ、詳細ページで全て表示される
5. 管理画面から削除すると、一覧・トップページ・詳細ページから消える（日記削除時は紐づく写真レコードも消える）
6. 未ログイン状態で `/admin` を直接開いてもフォームは表示されない（ログイン画面のみ）
7. 🆕 ログイン中はTOPページ上に「＋追加」ボタン（Things／Diary／Places）が表示され、モーダルから追加できる。未ログイン時は表示されない
8. 🆕 お店（Places）を写真付きで追加すると、`places-images` バケットにアップロードされ、TOPページ・詳細ページに反映される
9. 🆕 TOPページのカレンダーで、投稿がある日にドットが表示され、クリックするとその日の投稿（Things／Diary／Places）が表示される
10. Supabase未設定の状態でも、トップページ・管理画面はエラー画面にならず、案内メッセージが表示される
