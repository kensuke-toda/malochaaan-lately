## 1. プロダクト概要

**Lately** は、Ken とパートナーの2人で運用する近況報告サイト。買ってよかったモノ・行った店・読んだ本・聴いた音楽・日々の投稿・やっている仕事を、なるべく手間なく記録・公開することを目的とする。

- **主用途**: 2人の記録＋知人に「最近何してるか」を見せる公開ページ
- **ユーザーモデル**: Ken・パートナーの2アカウント。**1つの公開ページを2人で共有**し、それぞれが自分のアカウントでログインして投稿する（固定2アカウント運用、サインアップ画面なし）。投稿には誰が書いたかが分かるよう投稿者名を表示する
- **公開範囲**: トップページ・詳細ページ（全セクション共通）は誰でも閲覧可能（読み取り全公開）。投稿・編集は各自のログイン後のみ可能
- **投稿の起点**: `/admin`という別画面には依存しない。**ログイン中はTOPページ上に各セクションの「＋追加」ボタンが現れ、モーダルでその場から投稿できる**。`/admin`は一覧・編集・削除のみを行う補助画面
- **カレンダー**: TOPページにカレンダー（月表示）を置き、日付ごとにその日の投稿を振り返れる。**🆕2 Placesの投稿があった日は写真サムネイルをそのままセルに表示**。その他セクションの投稿がある日はセクションごとに色分けしたドットを表示。日付をクリックするとその日の投稿一覧を表示する
- **🆕2 セクション構成（6つ、元記事に準拠）**:

  | セクション | 内容 | Phase 1での位置づけ |
  |---|---|---|
  | Places | 行ったお店 | 対応（3Dジオラマなし） |
  | Things | 買ってよかったモノ | 対応（背景透過は手動アップロードのみ） |
  | Books | 読んだ本・読んでいる本 | 🆕2 新規対応 |
  | Sounds | 聴いた音楽 | 🆕2 新規対応 |
  | Posts | 日々の投稿（旧Diary） | 🆕2 旧Diaryを統合 |
  | Works | やっている仕事のサマリ | 🆕2 新規対応 |

- **デザイントーン**: スタイリッシュ・ミニマルではなく、**温かみのあるミッドセンチュリー・モダン**。**🆕2 背景は白ではなく、元記事サイトのような彩度のあるカーキ／クリーム色**を基調とし、テラコッタ・マスタード・ティール・プラム・オリーブ・ラストなど暖色〜アースカラーをセクションごとの差し色に使う。丸みのある形、セリフ寄りの見出しフォント

### やらないこと（明確な非スコープ）

- 3人以上のユーザー対応、オープンなサインアップ（アカウントは2人分のみ、Ken自身がSupabaseダッシュボードで手動発行）
- コメント機能・いいね機能などのソーシャル要素
- Places（お店）の**3Dジオラマ演出**（写真をそのまま使うシンプル版のみPhase 1に含む）
- Grok Bot等のチャット経由投稿（LINE Botのみ、Phase 2で検討）
- Books/Notion読書DB連携、Sounds/ストリーミングAPI連携などの自動取得（Phase 1は手動入力のみ）
- Things一覧の並び替えUI・各セクションの編集機能（Phase 1では対象外。削除して追加し直す運用でカバー）
- 独自ドメイン（Phase 1は `*.vercel.app` のまま運用）

## 4. 機能仕様

### 4.1 認証（管理画面）

- Supabase Authのメール＋パスワード認証を使用。アカウントは2つのみ（Ken・パートナー）で、**サインアップ画面は作らない**。Ken自身がSupabaseダッシュボードで2アカウントを手動作成する運用（決定済み）
- `profiles` テーブル（`id` は `auth.users.id` と1:1、`display_name` を持つ）を新設し、投稿者の表示名を解決する
- 各コンテンツテーブルに `created_by`（`auth.users.id`）カラムを追加し、誰の投稿か記録する
- どちらのアカウントでも全セクションへの追加ができる。**編集・削除は自分の投稿のみ**（決定済み。パートナーの投稿は編集・削除不可）
- RLS: `select` は全公開。`insert` は認証済みユーザーのみ（`created_by = auth.uid()` を強制）。`update`/`delete` も `created_by = auth.uid()` の行のみ許可
- 公開ページ（トップ・詳細）で投稿者の表示名を表示する
- 既存の `ADMIN_PASSWORD` ベースの実装（`src/lib/admin-auth.ts`）は撤去し、Supabase Authのセッション管理に置き換える

### 4.8 公開ページの表示ロジック

- トップページ: 各テーブルを最新順（Placesは`visited_date`降順、他は`created_at`降順、Postsは`entry_date`降順）に最大24件（Posts/Booksは最大10〜24件）表示
- 詳細ページ: `id` 指定で1件取得、存在しなければ404 (`notFound()`)
- Supabase未設定（環境変数がプレースホルダーのまま）の場合、公開ページはエラーにせず「Supabaseが未設定です」という案内を表示し、詳細ページは404を返す

### 4.8.1 「最近のあれこれ」（TOPページ冒頭）

6セクション横断のハイライト。参考サイトの同名ブロックに相当する。

- **対象**: 表示中の月（デフォルトは今月）に属する投稿。日付キーはカレンダーと同じ（Places=`visited_date`、Posts=`entry_date`、Things/Books/Sounds/Works=`created_at`の日付部分）
- **件数**: **セクションごとに**、日付の新しい順で **最大5件**。全体で5件にまとめるのではない。当月0件のセクションはその見出しごと出さない。6セクションとも0件ならブロック自体を出さない
- **UI**: セクションごとに**アコーディオン**（初期は閉じた状態）。見出しに件数を出す。複数セクションを同時に開いてよい
- **並び**: セクションの表示順は Places → Things → Books → Sounds → Posts → Works。同一セクション内は日付の新しい順。同じ日に複数ある場合は `created_at` の新しい順
- **1行の表示**: タイトル（リンクは各詳細ページ）。見出しで種別を示す
  - Places → 見出し `行った場所`、行は店名
  - Things → 見出し `モノ`、行は商品名
  - Books → 見出し `読んだ本`、行は書名
  - Sounds → 見出し `聴いた音楽`、行は曲名
  - Posts → 見出し `投稿`、行は本文の先頭
  - Works → 見出し `仕事`、行はタイトル

### 4.9 カレンダー

- TOPページに月表示のカレンダーを設置
- **🆕2 Placesの投稿があった日は、日付セルにその店の写真サムネイルをそのまま表示**（元記事のカレンダー表現に準拠）
- **写真セルをタップすると拡大モーダル**を開く。店名・日付・詳細ページへのリンクを表示する
- **同じ日にPlacesが2件以上ある場合**: セルには**いちばん新しい店の写真**を出し、右下に件数バッジ（`2` など）を付ける。モーダル内は左右送り（またはスワイプ）でその日の店を順に見る。セルを2分割したり重ねて全部出すのは、マスが小さいので採用しない
- 1件の店に写真を複数枚載せることは Phase 1 ではしない（Placesは写真1枚）。同じ日に店が複数あるケースだけを「2枚以上」として扱う
- その他セクション（Things/Books/Sounds/Posts/Works）の投稿がある日は、セクションごとに色分けしたドットで表示：Things=マスタード、Posts=ティール、Books=プラム、Sounds=オリーブ、Works=ラスト（複数種別があれば複数ドット。Places写真がある日はドットではなく写真優先）
- 日付をクリックすると、その日の投稿一覧（6セクション横断）をカレンダー下に表示する。写真セルのタップでも同様に下の一覧を更新する
- 対象日の判定キー：Places=`visited_date`、Posts=`entry_date`、Things/Books/Sounds/Works=`created_at`の日付部分
- 月送り（前月／今月／次月）は最低限対応

## 6. データモデル

現行スキーマ（実装済、`supabase/schema.sql`。🆕2 リネーム・追加が必要）:

```
things
  id (uuid, PK)
  name (text, not null)
  brand (text, null可)
  product_url (text, null可)
  original_image_url (text, null可)
  processed_image_url (text, null可)
  memo (text, null可)
  sort_order (integer, default 0)
  created_by (uuid, FK -> auth.users.id, not null)
  created_at (timestamptz, default now())

-- 🆕2 旧 diary_entries / diary_photos を改名
posts
  id (uuid, PK)
  body (text, not null)
  entry_date (date, default current_date)
  created_by (uuid, FK -> auth.users.id, not null)
  created_at (timestamptz, default now())

post_photos
  id (uuid, PK)
  post_id (uuid, FK -> posts.id, on delete cascade)
  image_url (text, not null)
  sort_order (integer, default 0)

places
  id (uuid, PK)
  name (text, not null)
  visited_date (date, default current_date)
  image_url (text, null可)
  memo (text, null可)
  created_by (uuid, FK -> auth.users.id, not null)
  created_at (timestamptz, default now())

-- 🆕2 新規
books
  id (uuid, PK)
  title (text, not null)
  author (text, null可)
  status (text, default 'finished')  -- 'reading' | 'finished'
  image_url (text, null可)
  memo (text, null可)
  created_by (uuid, FK -> auth.users.id, not null)
  created_at (timestamptz, default now())

-- 🆕2 新規
sounds
  id (uuid, PK)
  title (text, not null)
  artist (text, null可)
  image_url (text, null可)
  url (text, null可)
  memo (text, null可)
  created_by (uuid, FK -> auth.users.id, not null)
  created_at (timestamptz, default now())

-- 🆕2 新規
works
  id (uuid, PK)
  title (text, not null)
  period_label (text, null可)
  summary (text, null可)
  created_by (uuid, FK -> auth.users.id, not null)
  created_at (timestamptz, default now())

profiles
  id (uuid, PK, FK -> auth.users.id)
  display_name (text, not null)
```

**RLS方針**: `select` は全テーブル・全公開（`using (true)`）。`insert` は認証済みユーザーが `created_by = auth.uid()` で自分の投稿として作成。`update`/`delete` は **`created_by = auth.uid()` の行のみ**許可（自分の投稿のみ編集・削除可、決定済み）。

**Storage**: `things-images` / `places-images` / `books-images` / `sounds-images` / `posts-images` の5バケット、すべて `public: true`（読み取り公開）。書き込みは認証済みユーザーからの直接アップロード（Storageポリシーの追加が必要）。Worksは写真を持たないためバケット不要。

## 7. 受け入れ条件（Phase 1）

1. `supabase/schema.sql`（🆕2 改名・追加分反映後）を実行したSupabaseプロジェクトに接続すると、トップページで6セクション（Places/Things/Books/Sounds/Posts/Works）が表示される
2. Supabase Authで正しいアカウントでログインできる。誤ったパスワードではログインできない
3. TOPページの「＋追加」ボタンから、画像付きでモノ・お店・本・音楽を追加すると、対応するバケットにアップロードされ、トップページに反映される
4. TOPページの「＋追加」ボタンから、複数写真付きで投稿（Posts）を追加すると、`posts-images` バケットにアップロードされ、詳細ページで全て表示される
5. TOPページの「＋追加」ボタンから、仕事（Works）をタイトル・期間・サマリで追加すると、トップページに反映される（写真なし）
6. `/admin`から削除すると、一覧・トップページ・詳細ページから消える（投稿削除時は紐づく写真レコードも消える）
7. 未ログイン状態では「＋追加」ボタンが表示されない。`/admin`を直接開いてもフォームは表示されない（ログイン画面のみ）
8. 🆕2 TOPページのカレンダーで、Placesの投稿がある日はその店の写真がセルに表示され、タップで拡大モーダルが開く。同じ日に2件以上ある場合は最新写真＋件数バッジで、モーダル内を左右送りできる。他セクションの投稿がある日は色分けドット。日付クリックでその日の投稿一覧が表示される
9. 🆕2 TOPページ冒頭の「最近のあれこれ」は、当月の投稿を**セクションごとアコーディオン**で日付の新しい順・最大5件表示する。初期は閉じる。0件のセクションは出さない。全セクション0件の月ではブロック自体が出ない
10. Supabase未設定の状態でも、トップページ・管理画面はエラー画面にならず、案内メッセージが表示される
